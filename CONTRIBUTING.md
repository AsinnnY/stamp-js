# Contributing

Thank you for your interest in contributing to stamp-js!

## Development setup

```bash
git clone <repo-url>
cd stamp-js
npm test          # node --expose-gc test/run.mjs
```

Requirements: Node.js 18+.

## Project structure

```
src/stamp.js           Main source (zero-dependency ESM)
dist/stamp.umd.js      UMD build (generated by scripts/build-umd.mjs)
test/run.mjs           Test suite (unit + regression; see CI for the count)
test/fixtures.mjs      Hand-crafted ISO-BMFF / JPEG / PNG test samples
examples/              Usage examples
```

## Guidelines

### Code style
- Zero runtime dependencies. The library must work in browsers, Node, Deno,
  and Web Workers without any `npm install`.
- Comments in English. JSDoc for all exported APIs.
- No brand names, marketing language, or project-internal references in
  source code or comments.

### Testing
- Every bug fix must include a regression test in `test/run.mjs`.
- The test suite uses a minimal assertion framework (no test runner
  dependency). Run with `node --expose-gc test/run.mjs`.
- Test samples are constructed programmatically in `test/fixtures.mjs` —
  no binary fixtures needed.
- Corrupt/malformed inputs live in `test/malformed.mjs` (`npm run test:fuzz`).
  Each case asserts the same five invariants rather than a hand-written
  expectation: no throw, refuse-with-reason on failure, structurally valid
  output, byte-identical media payload, and idempotency. Add a case there
  whenever you touch a parser.

### CI

Three tiers, all in `.github/workflows/ci.yml`:

| Tier | Trigger | Contents |
|---|---|---|
| 1 `tier1-gate` | every push / PR | `npm test` on Node 18/20/22 (includes the sparse 4/8 GiB suites), UMD build + smoke, `dist/` in sync with `src/` |
| 2 `tier2-verify` | every push / PR | fuzz/malformed matrix, exiftool + Pillow interop, independent verification |
| 3 `tier3-release` | release tag / manual | real device material, ffprobe cross-check |

The Python suites (`test:interop`, `test:verify`, `test:ffprobe`) **exit 2** when
a third-party tool is missing, rather than reporting success they cannot
justify. In CI the tools are installed, so a non-zero exit is a real failure.

### Pull requests
1. Fork the repository and create a branch from `main`.
2. Add tests for any new functionality or bug fix.
3. Ensure `npm test` passes with 0 failures.
4. Update `CHANGELOG.md` under the `[Unreleased]` section.
5. Keep commits focused; squash if necessary.

### Adding a new format
1. Implement a `planXxx()` function that returns `{ format, edits,
   bytesReadFor }`.
2. Register it in `writeTags()` and `inspect()`.
3. Add test fixtures and assertions.
4. If the format has absolute offsets (like fMP4 or WebM), document the
   refusal behavior clearly.
